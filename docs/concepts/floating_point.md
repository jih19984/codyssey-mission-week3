# 부동소수점 오차와 epsilon 비교

## 원래 실험 코드 (test.py에서 이동)

```python
from decimal import Decimal
print(Decimal(0.1))
```

`Decimal(0.1)`을 출력해보면 `0.1`이 아니라 `0.1000000000000000055511151231257827021181583404541015625`처럼
길게 나온다. 이는 0.1이라는 값을 이진수(IEEE 754)로 정확히 표현할 수 없어서, 가장 가까운 이진 근사값이
저장되기 때문이다.

## 이게 이번 과제와 무슨 상관인가

- MAC 연산 결과(점수)도 float이다. 필터/패턴 값 자체는 0/1이라 하더라도, 누적합 과정에서 연산 순서나
  중간값에 따라 미세한 오차가 생길 수 있다.
- 두 점수가 "이론적으로는 같아야 하는데" `score_a == score_b`가 `False`로 나오는 경우가 생길 수 있다.
- 그래서 정확히 `==` 로 비교하지 않고, `abs(score_a - score_b) < 1e-9` 같은 **허용오차(epsilon) 기반 비교**를
  사용해야 한다. (`mac_engine.py`의 `EPSILON`, `judge()` 참고)

## data.json의 size_13_3 케이스와의 연결

`data.json`의 `size_13_3` 패턴은 13×13 전부 1로 채운 입력이다. cross/x 필터 모두 1의 개수가
`2*13-1 = 25`개로 동일하기 때문에 두 점수가 정확히 25.0으로 같다 (정수 연산이라 float 오차 없이도 동점).
이건 "동점 자체를 UNDECIDED로 처리하는 판정 정책"을 테스트하기 위한 케이스이고, 실제 float 오차로 인한
동점(예: 0.9 vs 0.8999999999999999)은 필터/패턴에 정수가 아닌 가중치가 섞이는 경우에 더 두드러질 수 있다.
어느 쪽이든 결론은 같다: **점수 비교는 항상 epsilon 기준으로 해야 한다.**
